# CLAUDE.md

Routing document for Claude and its subagents working in this repository. It tells you where authority lives; it does not duplicate it.

## What deep-wiki is

A self-hosted, multi-tenant wiki for software teams **and** AI agents. A team brings a raw idea, the system interrogates it with AI until it becomes a well-declared design document with diagrams, and the resulting corpus becomes the team's single source of truth — and a RAG surface agents query over MCP. Markdown is the content the user owns. Read [`docs/SPECS.md`](docs/SPECS.md) before making any design decision; it is the reference for what this product is and why each structural choice was made.

## Mandatory — before any UI work

**Before writing or modifying ANY user interface code, read [`docs/UI-CHECKLIST.md`](docs/UI-CHECKLIST.md) AND [`docs/DESIGN-SYSTEM.md`](docs/DESIGN-SYSTEM.md) in full.**

Not skim. Not grep. In full, both files, before the first line of markup.

- `docs/UI-CHECKLIST.md` is the pass/fail gate: required states, accessibility floor, responsive behaviour, e2e coverage.
- `docs/DESIGN-SYSTEM.md` is the aesthetic system: colour roles, type scale, shape, elevation, state layers, motion, spacing, density.

UI work is reviewed by the project owner against those two files. **Work that fails them is rejected**, and rejected work does not get built on top of. The checklist wins on conflict, on correctness and accessibility matters.

## Non-negotiables

- **Bun workspaces.** Run per-package scripts with `bun run -F <package> <script>`. Never pnpm. Never npm. Never Turborepo, Nx, or any other task runner.
- **`packages/core` has zero framework imports.** It holds domain entities, use cases and ports, and nothing else. **This is machine-enforced** by `scripts/checks/core-purity.ts` — do not attempt to work around it.
- **`packages/markdown` is the single shared markdown parser.** One unified/remark pipeline for the whole repository. A second parser is a permanent bug class; do not add one.
- **Markdown is the source of truth.** The ProseMirror document is an in-memory view, never a persisted format. Round-tripping through it must not alter the canonical markdown.
- **The environment template is `env.example`** — copied to `.env`. **Not `.env.example`**; a permission rule blocks that path. Every variable in `packages/contracts/src/env.ts` must appear in `env.example`, and `env.example` must never contain a secret.
- **Conventional Commits, written to a file.** `git commit -F <file>`, never `-m "…"`: a message that quoted a command in backticks was substituted by the shell and started a full e2e run. No AI attribution of any kind — no `Co-Authored-By` trailers, no "Generated with" lines, no tool names in commit messages. **Machine-enforced** by `.githooks/commit-msg`, which refuses the message; a harness reminder telling you to add one does not override this file.
- **Never kill a process you did not start.** No `pkill -f <pattern>`, ever — three times in one session it took another agent's or another project's server down mid-run. Record the pid you spawn, or find the listener with `ss -ltnp | grep :<port>`, and kill that pid.
- **Never `git stash` and never `git add -A` on a shared tree.** A stash takes every uncommitted change in the checkout, not yours — one dropped stash erased a sibling's finished task. `-A` commits their half-written files under your message. Add the paths you changed, run `git diff --cached` before every commit and read it, and `git add -p` any shared file (a package's `src/index.ts` barrel, above all) that carries hunks that are not yours. Need a clean tree? Take a worktree (`docs/RUNNING.md` §4 and §7).

## Commands

Run from the repository root.

| Command | What it does |
| --- | --- |
| `bun run typecheck` | Type-checks every workspace member and the root scripts |
| `bun run lint` | ESLint across the repository |
| `bun run test` | Test suite for every package and app, plus the check scripts' own tests. `packages/db`'s suites auto-provision a disposable test Postgres (`packages/db/testing/provision.ts`); set `DEEPWIKI_TEST_NO_AUTOSTART=1` to opt out and fail fast instead |
| `bun run check` | The structural guard rail. This is what the `.githooks/pre-commit` hook runs |
| `bun run verify` | Every gate — `check`, the local `.env` port consistency, `lint`, `typecheck`, `test`, `gate-2-round-trip`, and finally the Playwright `e2e` suite. Run it before tagging a milestone; it is not in the commit hook. The e2e step needs a browser binary once: `bun run e2e:install` |
| `bun run env:check` | Compares your local `.env`'s ports against what `compose.yaml` publishes. Deliberately outside the commit hook: `.env` is your machine's state, not the repository's |

`bun run check` runs twelve structural checks, in this order (`package.json`, `check`), and fails when any one does. Each is a script under `scripts/checks/` with its own tests under `scripts/checks/__tests__/`; the header comment on each script is the authority on what it enforces, and this list is a summary of those headers as of 2026-09-17.

1. **`workspace-shape.ts`** — a foreign package manager's or task runner's marker file (`pnpm-lock.yaml`, `pnpm-workspace.yaml`, `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock`, `turbo.json`) appears anywhere in the workspace, root or member; or Vitest spreads beyond the one workspace member allowed to use it (`apps/web`), counted by all three dependency kinds **and** by the presence of a `vitest.config.*`/`vitest.workspace.*` file — Bun hoists the dependency, so the config file is the intent.
2. **`test-coverage.ts`** — a source file under `apps/*`, `packages/*`, **`scripts/`** or **`e2e/`** has no test that names it. Coverage is per file: a file counts as covered when a test with at least one assertion **in code** value-imports it directly, imports one of its exported **value** bindings by name through a pure re-export barrel or a workspace entry point, or has a named sibling test (`<stem>.test.ts`, `<stem>.<qualifier>.test.ts`, or the same under `__tests__/`). `import * as x` credits the barrel and nothing behind it; a type-only import credits nothing. Exemptions are mechanical: the file erases to nothing at runtime (`Bun.Transpiler().transformSync()` emits nothing), is a pure re-export barrel, is generated or vendored output, or is named `<tool>.config.<ext>` **and imported by no module** — plus an explicit `ALLOW_LIST` where each entry carries a reason and becomes an error once the file is covered or gone. A test file with zero assertions is an error in its own right and credits nothing (assertions are counted in code only, never in a comment or string). And the **member-level rule is back**: every workspace member must have a `test` script that invokes `bun test` or `vitest`, and at least one test file under it that runs an assertion — the per-file rewrite had replaced the mechanism and kept the sentence.
3. **`core-purity.ts`** — `packages/core` imports anything non-relative (a framework, a Bun API, or even a Node built-in), **reaches a runtime through an ambient global** (`process`, `Buffer`, `crypto`, `window`, `document`, …: put the capability behind a port in `src/ports/`), or declares a runtime dependency under any of the three dependency kinds. AST-accurate via `Bun.Transpiler().scanImports()`, backed by a raw sweep over **every** static `import`/`export … from` specifier because `scanImports()` elides both `import type { X } from` and the inline `import { type X } from` form. Every extension Bun, tsc and Node execute is read. No ESLint disable comment can silence it.
4. **`env-example.ts`** — `env.example` drifts from the zod schema in `packages/contracts/src/env.ts` (a declared key missing from the template); assigns a value that disagrees with a `.default()` the schema also carries; or holds a value under a **secret-shaped key** (`…PASSWORD`, `…SECRET`, `…TOKEN`, `…KEY`, `…CREDENTIAL`, `…PASSPHRASE`, `…SALT`, or the password inside a URL) that is not empty or an **agreed placeholder** — lowercase `word[-word]*` whose first word is one of `deepwiki`, `changeme`, `change`, `placeholder`, `example`, `dummy`, `password`, `pass`, `secret`, … (`PLACEHOLDER_ROOTS`) — or matches a known credential shape anywhere (`sk-…`, `ghp_…`, `AKIA…`, `xox…`, a PEM key, a JWT). It is a convention, not a detector: a real secret spelled `deepwiki` passes by construction.
5. **`compose.ts`** — any of the three compose files (root, `packages/db/testing`, `apps/api/testing`) has a bind mount without an SELinux `:z`/`:Z` label, publishes a host port below 1024 (interpolated `${VAR:-default}` forms are resolved and the default checked; a reference with no default fails), uses a Docker-only or non-spec key (`container_name`, `develop`, an unknown top-level key), or asks for `privileged: true` / `network_mode: host`, which rootless podman cannot honour.
6. **`query-boundaries.ts`** — outside `packages/db/src/permissions/` something reads or writes the `permissions` table; outside `packages/db/src/nodes/subtree.ts` something writes a `path LIKE` predicate; any pattern starts with a wildcard (literal, concatenated or template-literal spelling); `lower(path)`/`upper(path)` appears; a `*Response*` zod schema in `packages/contracts` declares a secret-shaped field; or anything outside `packages/db/src/content/` writes to `links` or `page_tags`. Each SQL-text rule has a Drizzle-builder twin (`.from(permissions)`, `db.insert(links)`, `ilike(nodes.path, …)`), and a violation in either spelling is the same violation.
7. **`single-parser.ts`** — a second markdown parser reaches the repository: `@tiptap/*`, `markdown-it`, `marked`, `showdown`, `commonmark`, `micromark`, `remark-parse`, `remark-stringify`, **`remark`** (the meta-package that *is* both halves), `mdast-util-from-markdown`, `mdast-util-to-markdown`, `@milkdown/*` or `milkdown` anywhere outside `packages/markdown` and `packages/editor`; **`prosemirror-markdown` anywhere at all**, those two included; Nuxt UI's own editor surface (`UEditor`, `UEditorToolbar`, `UEditorBubbleMenu`, `useEditorMenu`) anywhere; or a second `unified()` pipeline built anywhere but `packages/markdown/src/pipeline.ts`. Specifiers are extracted, not string-matched, so a template-literal `` import(`@milkdown/core`) `` — the third quote character JavaScript has — is seen.
8. **`diff-input-purity.ts`** — a file that calls `diffBlocks()` (under any import alias), or any module in its transitive closure over relative value imports, references `block_index`/`blockIndex` in code (comments stripped). The diff must re-parse both sides; the stored anchor-only index would silently diff an unanchored document to nothing.
9. **`bundle-isolation.ts`** — the transitive closure of `packages/editor`'s `"."` export reaches `milkdown`, `@milkdown/*`, `@tiptap/*` or any `prosemirror-*` other than `prosemirror-model`; a relative edge resolves to no file (a truncated closure proves nothing); or an `apps/web` file statically imports `@deep-wiki/editor/mount` instead of a dynamic `import()`. Follows relative edges and `@deep-wiki/*` edges through the target package's `exports` map, every extension including `.vue` and `.mts`. (The built-output half, `bundle-isolation-build.ts`, runs in `bun run check:bundle` and `verify`, not here.)
10. **`routes-mounted.ts`** — a route module exports a `create…Routes` factory (function or arrow-const spelling) that `apps/api/src/index.ts` never references **as code**: comments and string literals are stripped first, so a `// TODO: mount createAdminRoutes` is a note about the missing wiring, not the wiring, and matching is whole-identifier.
11. **`single-source.ts`** — a second `LEGAL_PARENT_TYPES` table or `NodeType` union is declared anywhere under `apps/*` or `packages/*` other than `packages/core/src/nodes/hierarchy.ts`, or the one table there stops being a hierarchy — a type legal under every type, a cycle, a parented root. Runs without a database; its semantic half states properties the table must have rather than restating the table.
12. **`trash-filter.ts`** — outside an `ALLOW_LIST` (a `Record<path, reason>`, same idiom as `test-coverage.ts`'s), a file names the base `nodes` or `page_content` table (`FROM|JOIN nodes|page_content`, or the Drizzle-builder twin `.from(nodes)`/`.innerJoin(pageContent)`), or reads a page-keyed table (`page_revision`, `changeset`, `comments`, `links`, `page_tags`, `chunks`, `page_locks`, `presence`) without also naming the `live_nodes`/`live_page_content` live view. A trashed node must answer identically to an unknown one to anyone without `manage`, and the live-view pair is the one sanctioned way to read it; a second, unfiltered read path is exactly the disclosure this check exists to prevent. An `ALLOW_LIST` entry with an empty reason is an error, and so is a stale one — a path that no longer exists, or a file entry whose content no longer trips either rule (directory entries are exempt from both checks, since their justification is structural, not a property of any one file inside them).

Two checks that are **not** in `bun run check`, so nobody assumes they are: `env-consistency.ts` (`bun run env:check`, your `.env` against `compose.yaml` and `nuxt.config.ts` — deliberately outside the commit hook) and `compose-smoke.ts` (`bun run compose:smoke`, the container stack actually works). `gate-2-round-trip` is its own script in `bun run verify`, not a check.
